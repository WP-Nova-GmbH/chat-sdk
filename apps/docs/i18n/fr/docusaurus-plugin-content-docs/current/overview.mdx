# Nova Chat SDK

## Vue d’ensemble

Le Nova Chat SDK est le package navigateur qui monte une iframe de chat hébergée par Nova dans une page appartenant au client. Il est volontairement léger : le SDK gère le lanceur, le conteneur iframe, la transmission du token et le bridge `postMessage`. L’iframe gère l’interface de conversation et communique avec les services Nova au moyen d’un token de session intégrée à courte durée de vie.

Le navigateur ne reçoit jamais de secret d’intégration. Votre app expose un `tokenEndpoint` qui authentifie l’utilisateur courant, appelle `POST /embed/session` de Nova depuis le serveur, puis renvoie la réponse de session intégrée au SDK.

Le bridge du SDK gère trois capacités de la page hôte :

- Des instantanés de page qui résument le texte visible, les liens, les contrôles, les libellés, la sélection et les valeurs de champ sûres.
- Des actions de navigation intégrées sur des handles d’éléments stables issus du dernier instantané.
- Des outils d’intégration définis par le SDK, enregistrés avec leur contrat
  complet et leur handler via `registerTool`. Le réglage Page Tools de la
  surface est uniquement l’autorisation côté serveur.
- Des outils backend côté serveur et des workflows
  `research-and-compose` configurés par `pageWorkflows`, déclenchés seulement
  après la readiness exacte de la page.

Nova peut aussi afficher `request_user_input` comme carte de choix interactive
dans l’iframe. Cet outil de conversation et les actions de page intégrées ne
s’enregistrent pas dans la page hôte.

## Modèle d’exécution

1. Un administrateur Nova crée la surface et configure les origines, Page
   Reading, Page Navigation et Page Tools.
2. Le backend conserve le secret et expose un `tokenEndpoint`.
3. La page appelle `WpNova("init", { publicSurfaceId, tokenEndpoint })`.
4. Le SDK monte `<wp-nova-chat>`, authentifie l’iframe et transmet les
   instantanés, routes et spécifications d’outils enregistrées.
5. Après une action, le SDK attend que la vue cible soit rendue avant d’envoyer
   le nouvel instantané.
6. Un utilisateur inconnu reste indisponible en `existing_only` ; une surface
   JIT confirmée peut créer une adhésion active avec un token de création limité.
